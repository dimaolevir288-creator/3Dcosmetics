# 3DCosmetics

3D-косметика для **Paper 1.21.11** на Kotlin (Java 21).

Плагин рисует косметику (шляпы, плащи, крылья, наручи, обувь) через сущности
`ItemDisplay`, которые «катаются» на игроке. Выдача прав идёт через **LuckPerms**,
покупка — через **Vault**, данные хранятся в **YAML**.

Косметика **не занимает слоты брони и инвентаря** — это отдельные сущности,
поэтому шляпа спокойно носится вместе с настоящим шлемом.

## Слоты

Каждая косметика крепится к одной из четырёх частей тела:

| Слот | Что туда вешают | Точки крепления (`anchor`) |
|---|---|---|
| `head` | шляпы, маски, рога | `head` |
| `body` | плащи, крылья, рюкзаки | `chest`, `back` |
| `arms` | наручи, перчатки | `left_arm`, `right_arm` |
| `legs` | сапоги, наколенники | `feet`, `left_leg`, `right_leg` |

В одном слоте активна одна вещь, разные слоты складываются
(шляпа + плащ + наручи + сапоги одновременно).

Слот задаётся в `cosmetics.yml` полем `slot`. Если его нет — выводится из `anchor`,
а при импорте из Blockbench — из имени файла или костей модели.

## Цены по слотам

```yaml
prices:
  head:
    default: 2500.0    # цена, если у косметики нет своего price
    multiplier: 1.0    # множитель для всего слота
```

Итог = `(price косметики или default слота) × multiplier`.

## Примерка без покупки

Каждый предмет можно примерить **один раз** на несколько секунд:

- **ПКМ** по кнопке в меню или `/cosmetics trial <id>`;
- предмет надевается и через `trial.duration-seconds` (по умолчанию 5) снимается сам;
- предыдущая вещь в том же слоте возвращается на место;
- использование сохраняется в `players/<uuid>.yml` (`trials`) и не сбрасывается перезаходом.

```yaml
trial:
  enabled: true
  duration-seconds: 5
```

Отключить примерку для конкретной вещи: `trial: false` в её записи.

## Возможности

- Слоты косметики по категориям: шляпа + плащ + крылья надеваются одновременно,
  но в пределах одной категории активна только одна вещь.
- Меню `/cosmetics`: категории → список косметики с кнопками
  «Купить / Надеть / Снять».
- Покупка через Vault. Если Vault нет — меню работает, но покупки отключены.
- Выдача через LuckPerms: права вида `cosmetics.hat.crown`.
- Админ-команды `give` / `take` / `reload`.
- Хранение в `plugins/3DCosmetics/players/<uuid>.yml`, асинхронная запись.

## Новое

- **`info.txt`** — создаётся рядом с `config.yml` при каждом включении сервера.
  Содержит полное описание: команды, права, формат конфигов, инструкция по
  ресурспаку и добавлению своей косметики, раздел с частыми проблемами.
- **Ресурспак в папке плагина** — при старте плагин распаковывает шаблон в
  `plugins/3DCosmetics/resourcepack/` и собирает готовый
  `plugins/3DCosmetics/3DCosmetics.zip` (с расчётом SHA-1).
- **Обязательная загрузка пакета при входе** — `resource-pack.force: true`:
  клиент не может отказаться, иначе не зайдёт на сервер.
- **Русский язык** — `language: ru_ru` в `config.yml`.
  Встроенные локали: `lang/messages_ru_ru.yml`, `lang/messages_en_us.yml`.
  Файл `messages_ru_ru.yml` в папке плагина перекрывает встроенный.

## Модели из Blockbench

Плагин сам пересобирает `.bbmodel` в формат ресурспака — вручную
конвертировать и раскладывать файлы по папкам не нужно.

1. Сделайте модель в Blockbench (формат **Java Item** или CPM).
2. При сохранении включите **Embed Textures**, чтобы текстуры попали внутрь файла.
3. Скопируйте `.bbmodel` в `plugins/3DCosmetics/blockbench/`.
4. Выполните `/cosmetics import` (или `/cosmetics import force`, чтобы пересобрать всё).

Плагин разберёт модель, приведёт геометрию к системе координат модели
предмета Minecraft и запишет её в ресурспак:

```
assets/3DCosmetics/models/item/<имя_файла>.json
assets/3DCosmetics/textures/item/<имя_файла>.png
```

Затем он пересобирает `3DCosmetics.zip` и отправляет пакет всем игрокам онлайн.

Для `top_hat.bbmodel` получится ключ `3DCosmetics:item/top_hat` — его
указывают в `cosmetics.yml`:

```yaml
my_hat:
  category: hats
  model:
    material: PAPER
    item-model: "3DCosmetics:item/top_hat"
    anchor: head
```

Что делает конвертер:

- разворачивает ось Y (Blockbench растёт вверх, модель предмета — вниз)
  и переназначает грани/UV, чтобы текстура не зеркалилась;
- центрирует модель по X/Z и ставит на макушку головы;
- «запекает» повороты костей (bones) в вершины — модель предмета
  не умеет вращать элементы;
- при нескольких текстурах добавляет к именам суффиксы `_0`, `_1`, …;
- пропускает mesh-элементы и анимации (ванильная модель предмета
  поддерживает только кубы).

Импорт идёт автоматически при старте сервера и при `/cosmetics reload`.
Неизменившиеся файлы пропускаются по SHA-1-хешу содержимого (`blockbench/*.importhash`).

## Сборка

```bash
./gradlew shadowJar -x test
```

Готовый jar: `build/libs/3DCosmetics-1.0.0.jar`.

> **Зависимости.** Paper API поставляется локальным файлом
> `libs/paper-api-1.21.11.jar` (скачан с `repo.papermc.io`, SHA-256 сверен с
> официальной контрольной суммой, содержимое проверено на вредоносный код:
> ни исполняемых файлов, ни вызовов `Runtime`/`ProcessBuilder`/`Socket`).
> Он подключён как `compileOnly`, поэтому не попадает в итоговый jar.
> `luckperms-api` — `compileOnly` из Maven Central.
> Vault API не публикуется в Maven Central, поэтому плагин обращается к нему
> через рефлексию — отдельный jar не нужен, а сборка не падает без него.

> **Тесты.** Прогон `test` в этом окружении падает на инфраструктуре
> (Gradle 9.6 + JDK 25: `ClassNotFoundException: GradleWorkerMain`), а не на коде.
> Собирайте с `-x test`; на сервере тесты не нужны.

## Установка

1. Положите jar в `plugins/`.
2. Установите **Vault** + любой плагин экономики (EssentialsX, CMI, …).
3. Установите **LuckPerms** (опционально, но рекомендуется).
4. Запустите сервер — создастся `plugins/3DCosmetics/`.
5. Настройте раздачу ресурспака (см. «Ресурспак» ниже).
6. Выполните `/cosmetics reload`.

## Ресурспак

### Вариант 1: GitHub Actions (рекомендуется для хостинга)

Порт 8123 на shared-хостинге недоступен снаружи, поэтому пак раздаётся
через GitHub Releases. Токен хранится в GitHub, а не на сервере.

1. Загрузите проект в GitHub-репозиторий (публичный).
2. Action `.github/workflows/resourcepack.yml` запустится сам при любом
   изменении в `src/main/resources/resourcepack/` и опубликует zip в Releases.
3. В `config.yml` замените `USER/REPO` на свои:
   ```yaml
   resource-pack:
     url: "https://github.com/ВАШ_НИК/ВАШ_РЕПО/releases/latest/download/3dcosmetics.zip"
   ```
4. Откройте ссылку в браузере — должен скачаться zip.

Ссылка постоянная: релизы создаются с тегом `pack-<номер>`, а `latest`
всегда указывает на свежий. Менять конфиг после обновлений не нужно.

### Вариант 2: свой хостинг файлов

Загрузите `plugins/3DCosmetics/3dcosmetics.zip` на любой файлхостинг
с прямой ссылкой и укажите её в `resource-pack.url`.

### Вариант 3: встроенный HTTP-сервер (только VDS)

Подходит, если можно открыть порт снаружи. Оставьте `url` пустым:

```yaml
resource-pack:
  url: ""
  http-server:
    enabled: true
    port: 8123
    host: "ваш-домен или IP"
```

## Команды

| Команда | Право | Описание |
|---|---|---|
| `/cosmetics` | `cosmetics.use` | Открыть меню |
| `/cosmetics give <player> <id>` | `cosmetics.admin` | Выдать косметику |
| `/cosmetics take <player> <id>` | `cosmetics.admin` | Забрать косметику |
| `/cosmetics off` | `cosmetics.use` | Снять всю косметику |
| `/cosmetics trial <id>` | `cosmetics.trial` | Примерить косметику на несколько секунд |
| `/cosmetics reload` | `cosmetics.admin` | Перезагрузить конфиги и ресурспак |
| `/cosmetics import [force]` | `cosmetics.admin` | Импортировать `.bbmodel` из `blockbench/` |

Алиасы: `/cos`, `/hat`, `/hats`.

## Выдача через LuckPerms

Каждая косметика в `cosmetics.yml` содержит `permission`. Достаточно выдать ноду:

```
/lp user Steve permission set cosmetics.hat.crown
```

Плагин считает косметику доступной, если нода есть у игрока — независимо от того,
куплена она в меню или выдана вручную. `/cosmetics give` дополнительно пишет ноду
через LuckPerms API и сохраняет вещь в локальные данные.

Чтобы забрать косметику навсегда, используйте:

```
/lp user Steve permission unset cosmetics.hat.crown
```

или `/cosmetics take Steve crown`.

## Конфигурация

- `config.yml` — экономика, интервал рендера, звуки, сообщения.
- `cosmetics.yml` — категории и определения косметики.

### Своя косметика

```yaml
cosmetics:
  my_hat:
    category: hats
    display-name: "&bМоя шляпа"
    description:
      - "&7Описание"
    icon: LEATHER_HELMET
    price: 1000.0        # 0 = бесплатно, отрицательное = не продаётся
    permission: "cosmetics.hat.my_hat"
    model:
      material: PAPER
      custom-model-data: 1005
      scale: 0.9
      translation: [0.0, 0.34, 0.0]
      rotation: [0.0, 0.0, 0.0]
      anchor: head        # head | back | chest | feet
      billboard: FIXED
```

### Якоря (`anchor`)

| Якорь | Относительно игрока |
|---|---|
| `head` | ~1.62 блока над ногами |
| `back` | ~1.20 блока, смещение назад |
| `chest` | ~1.20 блока по центру |
| `feet` | ~0.10 блока над землёй |

Поле `translation` задаёт смещение в локальных координатах игрока
(X — вбок, Y — вверх, Z — назад), поворачивается вместе с игроком.

## Ресурспак

В `src/main/resources/resourcepack/` лежит заготовка ресурспака
(`pack.mcmeta`, модели и `lang`). Текстуры положите в
`assets/3DCosmetics/textures/item/`. Соберите содержимое папки в zip
и раздайте игрокам — либо перенесите в свой серверный ресурспак.

## Структура

```
ru.hat1.cosmetics
├── 3DCosmeticsPlugin      — точка входа, связывание сервисов
├── command/                 — /cosmetics
├── config/                  — парсинг конфигов, сообщения
├── gui/                     — меню и обработка кликов
├── integration/             — Vault, LuckPerms
├── listener/                — join/quit/teleport
├── model/                   — модели данных
├── render/                  — ItemDisplay-рендер
├── service/                 — бизнес-логика покупки/надевания
└── storage/                 — YAML-хранилище
```
